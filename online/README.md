# 迷途神廟｜TEMPLE DUEL

獨立的 2–4 人線上遊戲：首頁 → 私人房大廳 → 即時對戰 → 回合／整場結算。沒有把單人模擬器藏在彈出視窗後面；原本根目錄的單人版與 `versus/` 不受影響。

## 啟動

```powershell
cd online
npm.cmd install
npm.cmd start
```

玩家用瀏覽器開啟 `http://localhost:3000`。若不在同一台電腦，請把伺服器部署到可公開連線、支援 WebSocket 的 Node.js 環境。

## 讓不同電腦點網址就玩

專案根目錄已附 `render.yaml`。部署後，玩家不必安裝 Node.js，也不必跟主辦者在同一個網路，只要開啟 Render 提供的 HTTPS 網址即可。

主辦者可複製含房號的邀請連結；受邀玩家開啟後先輸入自己的名稱，再按「加入房間」。私人房至少 2 人即可開局，最多 4 人（含房主），第 5 人會被拒絕。房主開始回合時，全員同步顯示 3、2、1 倒數，倒數結束前不能移動或取得勝利。

1. 推送專案根目錄的 `render.yaml` 與完整 `online/`（不用 `node_modules/`、`.env` 或測試截圖）。
2. 登入 Render，選擇 **New → Blueprint**。
3. 連接該儲存庫；Blueprint 路徑使用根目錄的 `render.yaml`。
4. 確認並部署 `lost-temple-private-room`。
5. 完成後分享 Render 產生的 `https://……onrender.com` 網址。

免費執行個體閒置後可能休眠，所以第一位玩家隔一段時間重新開啟時，需要等待伺服器喚醒。房間資料目前只存在伺服器記憶體內；重新部署或伺服器重啟後，舊房號會失效，重新建立即可。

## 房主權限

主辦者可在大廳調整：

- 官方佈局／程式生成迷宮
- 一般探門／數學探門／紅綠燈競速
- 獨立的捲軸視角開關，可搭配任一玩法；不再有黑霧遮擋
- 官方模式：真實機率／均勻隨機、隨機佈局／指定佈局編號 0–124
- 自訂勝利分數：1–99 的整數；1、3、5、7 是快捷按鈕，不是限制
- 是否共享撞門情報
- 回合結束是否顯示答案

設定更新和開局命令都會在伺服器再次檢查房主身分，訪客不能只靠修改瀏覽器畫面越權。

修改規則會重置比分，回合中設定鎖定。先到 E3 拿一分；達到目標分數才算贏得整場，房主可選「再來一場」。任何挑戰者離開都會取消回合、重置比分，剩下至少 2 人即可重新開局；房主離開則關閉整個房間。回合中不能中途加入；新玩家在大廳／結算後加入會重開比分，並取得空的席位，不會繼承離房者的分數。對戰畫面不顯示佈局編號，但房主仍可在大廳指定佈局。

1P 藍色、2P 粉色、3P 金色、4P 紫色，各自顯示名字、步數與比分。每個席位的起點不同且不重疊；玩家可以互相穿過，不會阻擋彼此。離房後其餘人的席位與顏色不會重新編號。

## 生成迷宮模式

`maze.js` 自行生成門的開閉，**不抽選、不拼接 125 張官方路線**。沿用 5×5 房間、A3 起點、E3 終點與 A3–B3 實牆：

- 生成兩條中間互不交叉的路，從起點左右分岔，到終點匯合。
- 不添加死路或額外支線：所有開啟的門都在兩條通關路線上，未使用的房間無法進入。仍保留真假門的探門玩法。
- 伺服器每回合生成一次，將同一張迷宮送給所有玩家。無論人數多少，迷宮仍維持兩條可通關的分岔。
- 生成後再驗證通關路線數恰為兩條；極端亂數下有保底可通關地圖。

「全新」代表每回合重新生成，沒有保存歷史去排除重複地圖。回合後揭曉兩條路線可由房主關閉。

操作：WASD 或方向鍵只控制自己的角色；手機提供方向按鈕。同步倒數結束前不能移動或計分，計時由伺服器共同起跑時間計算。

## 捲軸視角（無黑霧）

房主勾選 **捲軸視角**，可搭配一般／數學探門／紅綠燈，以及官方佈局或無死路的生成迷宮。這裡的捲軸是鏡頭捲動，不是羊皮紙介面。原本黑霧模式已改為純鏡頭捲動，舊 `fog` 設定會自動轉為 `scroll`。

- 盤面放大約 2.3 倍，鏡頭平滑跟隨自己的角色，接近地圖邊界時鏡頭停止越界。
- 沒有黑霧、視野半徑或牆後遮擋；鏡頭範圍內的房間與對手都會顯示。畫面外的區域只因放大而被裁切，不是被霧遮住。
- 門的真假仍需探門揭曉；數學模式仍需各自答對才能解鎖，移除黑霧不會自動公布門的答案。
- 探過的門與房間記錄仍會保存；共享探門情報照常同步。
- 回合後若允許揭曉路線，會切回完整地圖。隱藏路線時回到自己的捲軸視角；禁止揭曉時持續保留捲軸視角。
- 遵循系統「減少動態效果」設定，改用立即跟隨而非平滑捲動。

目前仍由瀏覽器模擬移動與鏡頭。

## 數學探門

房主在「遊戲玩法」選擇 **數學探門**。碰到自己還沒答對的門，就會取得一道簡單加、減、乘或除題；答案都是非負整數，除法一定整除。

- 題目以置中的彈出視窗顯示，自動聚焦答案欄；按 Esc 或點背景不能略過。答對、回合結束或離房時才關閉。
- 答錯保留同一道題，可不限次數重試；答對才解除自己的移動限制。
- 答題時只有自己不能移動，計時與對手的遊戲仍繼續。
- 開啟共享探門情報時，一人答對就會同步門的真假顏色給全員，但**不會取消其他人的題目，也不會幫其他人解鎖門**。
- 即使已看到共享的真假資訊，每位玩家仍須自己答對一次。真門才可通過；假門仍不能通過。同一回合自己已答對的門不必重答，新回合重新計算。
- 題目答案留在伺服器，由伺服器判定作答；不能用對手的題目 ID 代答，答題期間的移動與抵達終點回報也會被拒絕。

這仍是私人房原型，不是完整防作弊系統：地圖資料會送到瀏覽器，玩家移動與碰撞仍由瀏覽器模擬。

## 紅綠燈競速

房主在「遊戲玩法」選擇 **紅綠燈 · 紅燈動就回起點**；可搭配官方／生成地圖及獨立捲軸開關。

- 所有玩家使用伺服器提供的同一組燈號時程與起跑時間。每次綠燈約 3–5 秒、黃燈預告 0.8 秒、紅燈約 2–3.5 秒。
- 綠燈與黃燈可移動；紅燈時按移動鍵或手機方向按鈕，就會傳回自己的 A3 起點，即使撞牆沒改變位置也算違規。
- 只傳回違規玩家，不影響對手、比分、計時與已探過的門；步數繼續累計。被傳回後先放開按鍵，再重新出發。
- 伺服器判定紅燈違規並同步傳送位置，隔離傳送前的舊位置訊息；切紅燈時對延遲中的位置封包有 250 毫秒緩衝，已顯示紅燈的移動輸入則直接判定。
- 畫面以燈色、文字與倒數顯示狀態，不只依賴顏色辨識。這不是撞門答題模式，不會彈出數學題。
- 切換綠／黃／紅燈時，整個畫面會以對應顏色柔和閃爍一次（0.65 秒），不會持續快速閃光，也不攔截操作；離房、回大廳或結算會停止效果。系統開啟「減少動態效果」時，改用靜態彩色邊框。

## 本機測試

```powershell
cd online
npm.cmd install
npm.cmd run check
# 另一個 PowerShell 先啟動 npm.cmd start，再執行：
npm.cmd run test:integration
```

`check` 檢查模組語法、四人頁面 ID、角色配色與起點、125 張官方地圖及 1,000 張生成地圖，包含無死路、所有開門都在兩條通關路線上，以及角色碰撞半徑的通行測試。另驗證鏡頭跟隨與邊界、10,000 道數學題及 1,000 組紅綠燈時程。`test:integration` 驗證 2／3／4 個 Socket.IO 客戶端的權限、設定同步、倒數、自訂分數、整場勝利與離房，也測試第 5 人拒絕、四人獨立答題與情報共享、連續 20 次錯答、禁止代答、紅燈處罰／傳送後舊位置隔離／新回合重置，以及空席補位與房主關房。

桌機／手機瀏覽器自動測試（使用隔離的無頭瀏覽器）：

```powershell
$env:CHROME_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
npm.cmd run test:gui
```

沒有 Chrome 可用 `npx.cmd playwright install chromium`，省略 `CHROME_PATH` 即可。伺服器需先啟動；自訂網址可設 `$env:TEST_URL = 'http://localhost:3010'`。測試截圖放在已忽略的 `test-artifacts/`，測試會用真實鍵盤走完整條一般／捲軸生成路線、確認整場結算、鏡頭捲動、牆後房間可見、沒有黑霧遮罩與手機版沒有水平溢出；數學模式驗證各自答題及通關，紅綠燈模式驗證切換閃爍、減少動態替代提示與紅燈傳送。四個隔離瀏覽器另驗證四個角色、4P 手機觸控及完整通關、四人各自答題、3P／4P 起點傳送、三人空席位遊玩、補位與房主離房後全員退出。

目前定位是私人房原型：伺服器判定誰先抵達終點，但玩家移動仍由各自瀏覽器模擬。若要做公開排名或比賽，下一步應把碰撞與位置計算搬到伺服器端。
